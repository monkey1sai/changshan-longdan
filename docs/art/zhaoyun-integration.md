# 使用者趙雲模型整合紀錄

## 來源與製作結果

本次以本機 `a42c9294c32ac8ff566bc019dc5465b9dc7ad1d9` 為基準，在獨立 worktree 實作，保留主工作區既有未提交資料。使用者提供 `趙雲.blend`，SHA-256 為 `c8dff5bf7d43c04040a5f661b64a8702b5bedaf5fb2f69debd10a626dcc901a9`，原檔未修改。這不是先前 PR 的另一份趙雲素材。

實際檢查得到一個 30,000 三角形的融合網格，包含姿勢化雙手與長槍，沒有骨架、權重或動畫。三張 2048×2048 貼圖已內嵌（底色、金屬／粗糙、法線），有原始 UV。焊接後仍是一個相連網格，因此不能只把槍當成既有獨立物件取出。

在原檔副本上新增 21 骨骨架、四權重上限且正規化的蒙皮，包含雙手、雙腳、披風和裙甲。依實際肩肘腕與髖膝踝位置建骨與權重，不依動畫名稱猜測。將融合長槍沿已檢查的軸分離，保留原槍刃和裝飾，補建連續槍桿，校準為既有程序招式的長度／握點：局部 Z 為 -1.05～2.7 公尺。這會改變原靜態模型的槍長，目的是維持原招式視覺、刀光與判定的關係。

GLB 為 29,569 三角形、3,706,788 bytes，21 骨，零未加權頂點，三張內嵌貼圖，無外部 URI／額外解碼器。沒有新增時間獨立的動畫 clip；所有動作由既有姿勢與 Player 招式時間驅動。唯一 LOD 是目前模型，尚無低階硬體／多 LOD 驗收。

## 集中 adapter 與動作時間

- `src/view/zhaoyun-adapter.ts` 集中處理資源識別、骨骼名稱、bind pose 修正、骨長、手握槍姿態及皮膚載入。
- `src/view/player-model.ts` 繼續驅動程序姿勢；用真實骨架呈現待機／跑步／跳躍／防禦／閃避／受擊／倒地起身／死亡／無雙，以及 17 招。
- 正規雙臂 IK 和 `weapon-grip.ts` 約束槍柄在臂長內；雙手招式以共同槍軸握持，單手時依既有 `lh` 曲線釋放。
- 跑步腳步使用實際位移相位，著地段抵消身體移動；姿勢轉換沿用上一個腳點混合，停止後回到地面。
- 跑步時的骨盆高度補償也參與同一姿勢混合，避免直接出普攻時一幀上跳；碰撞位置不受這個外觀補償影響。
- 受擊轉身沿最短角度混合 0.12 秒；攻擊朝向最多混合 0.07 秒且早於第一命中窗口。碰撞朝向與傷害規則保持原本的 Player／MoveDef。
- `src/game.ts` 以 `simDt`／`simClock` 更新模型與披風；hitstop 同步凍結骨骼、槍尖、披風與刀光時間。武器從同一 driver 取得槍尖／刀光端點，不另加位移或 root motion。
- 新模型只有在網格、長槍與全部骨骼驗證完成後才隱藏體素回退；失敗會有明確 console error。開發環境 `__game.state.character` 提供唯讀識別與狀態，`animation` 提供握點／腳點／可見朝向；不在正式建置暴露 DEV 入口。

`entities/player.ts` 和 `combat/moves.ts` 未變更。速度、攻擊窗口、傷害、合法取消、格擋、無雙與重試規則保留。

## 重現匯出

使用 Blender 4.5.5 LTS。先複製使用者原檔到 repo 外證據目錄，再在副本執行；不要將副本輸出路徑設成原檔。

```powershell
& 'C:\Program Files\Blender Foundation\Blender 4.5\blender.exe' --background --factory-startup --disable-autoexec '<原檔副本.blend>' --python scripts/prepare-zhaoyun.py -- public/models/zhaoyun.glb '<repo外證據目錄>'
```

此腳本會檢查輸入副本的來源 SHA-256，針對這份來源網格和已檢查的解剖／槍軸座標製作；不同素材需要重新檢查，不是通用自動綁骨工具。整理後副本與 `prepared-audit.json` 寫入證據目錄。`public/models/zhaoyun.manifest.json` 留下來源／匯出雜湊、大小與對應狀態。

## 驗證與限制

工程驗證使用真實 GLB 幾何和骨骼；Node 測試只移除圖片引用避免假造影像解碼器，圖片載入以可見 Chrome 核對。測試涵蓋四權重、17 招前置揮動、握點、同招重觸發、正式連招／取消、hitstop、世界位移一次、腳底接地與不持續滑動、受擊轉向和重開。

可見 Chrome 的正式鍵盤／滑鼠操作與錄影見 repo 外驗收報告。使用自然充能、普通／精準格擋、受擊、倒地、死亡及 Enter 重開，沒有 DEV 改寫角色／敵人／血量或強制勝敗。正常速度及 0.25 倍速回看已保存播放證據。

影片為 1440×900、25 FPS、無音軌；本輪不包含音效聽感、實體手把、低階硬體及長時間穩定性。25 FPS 的錄影和部分混戰遮擋限制細小穿模的判斷，不能宣稱所有姿勢／鏡位永無自相交。披風沿用骨骼／Verlet 驅動，沒有新增完整的布料自碰撞系統。

同一 RTX 4060 Ti、300 名敵兵、1440×900、quality=1 的固定標題場景，在 18 秒暖機後取 12 秒：整合前後約 60 FPS、p95 16.8 ms。這是上限飽和，不能當改善證據；新模型的渲染計數包含陰影為 449,174 三角形（原 392,004），draw call 為 35（原 79）。
